## Core decisions

- Preview is generated by spawning `mkdocs serve` (do not use a JS markdown renderer as the source of truth).
- Editor is a structured document model (ProseMirror-based recommended) serialized deterministically to Markdown.
- Electron security defaults: no Node in the renderer; all privileged operations go via Preload Bridge + IPC.

## Process layout (Electron)

1. **Main process**
   - App lifecycle, window creation, permissions
   - Spawns/controls MkDocs runtime process
   - Performs filesystem access (read/write/CRUD)

2. **Preload**
   - Exposes a minimal, typed API to the renderer via `contextBridge`
   - Wraps IPC calls (request/response) and events (logs, preview status)

3. **Renderer (React)**
   - UI (tree/editor/preview panes)
   - Editor (Milkdown) runs here
   - Consumes the Preload API (never direct Node access)

## Modules

1. ProjectLoader (main)

- Locate `mkdocs.yml`, parse YAML, determine `docs_dir`, optionally parse `nav`.

2. FileSystemService (main)

- Read/write `.md`
- CRUD pages (create/rename/delete/move)
- Copy assets into project assets folder

3. MkDocsPreviewService (main)

- Spawn `mkdocs serve --dev-addr 127.0.0.1:PORT` in the selected project root
- Health-check port
- Capture logs and stream them to the renderer (IPC event)
- Restart on config changes if needed
- Stop process on project close/app exit

4. PreloadBridge (preload)

- `project.open()`, `project.getTree()`
- `page.read(path)`, `page.write(path, contents)`
- `preview.start()`, `preview.stop()`, `preview.status()`
- `preview.onLog(cb)` / `preview.onStatus(cb)`

5. EditorCore (renderer)

- WYSIWYG with block insertion
- Markdown import/export
- RawBlock round-trip (lossless)

6. PreviewPanel (renderer + main coordination)

- Loads `http://127.0.0.1:PORT` in a sandboxed view.
- MVP: `<webview>` limited to localhost URL only **or** a `BrowserView` managed by main.
  - Prefer `BrowserView` long-term to avoid enabling `webviewTag`.
  - If using `<webview>`, hard-block navigation away from localhost.

## Error handling

- If MkDocs is missing: show “Install/Configure MkDocs runtime” flow.
- If project uses unsupported plugins/extensions: preview still works (mkdocs renders); editor may disable unknown blocks but must not destroy content.
- If preview fails to start: show readable error + captured stdout/stderr + suggested fixes.

## Content safety rule

- When opening a page, if it contains unsupported syntax, preserve it (lossless mode):
- Keep raw markdown segments as “RawBlock” nodes that round-trip unchanged.
- If import/export cannot represent a region safely, it must become a RawBlock and round-trip unchanged.
